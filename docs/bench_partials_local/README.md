# Local bench partials — provenance

> **The per-technique JSONs are not committed.** They are regenerated by every
> run and are overwritten in place, which is exactly how this directory once
> ended up holding an n=50 `arditi.json` next to an n=20 `cheng.json` — one
> directory that reads as a single sweep but splices two sample sizes. Only
> this README is tracked; the committed result is
> `public/bench/refusal_bench_default.json`, which is written atomically at the
> end of a run and carries its own provenance fields.

Per-technique output from `backend/scripts/run_bench_local.py`. One JSON per
technique, written as each finishes so a crash mid-sweep does not lose earlier
rows. **Unlike `docs/bench_partials/`, these ARE reproducible by current code
and ARE strict JSON** (non-finite floats are mapped to `null` by
`runner.json_safe`).

## Why CPU and not MPS

TransformerLens emits `UserWarning: MPS backend may produce silently incorrect
results (PyTorch 2.12.0)` — see
[TransformerLens#1178](https://github.com/TransformerLensOrg/TransformerLens/issues/1178).
A number that may be silently wrong is worse than a number that took longer, so
the artifact of record is CPU. Two further practical notes from the MPS attempt:

- MPS held ~11 GB RSS for this 1B model (fp32 load, then cast) and drove a 16 GB
  machine into swap exhaustion; the same run on CPU sits at ~4–5 GB.
- The CPU path was *broken* until July 29: `run_bench_local.py` casts to
  bfloat16 on CPU, and torch cannot convert bfloat16 to numpy at all, so probe
  training died with `TypeError: Got unsupported ScalarType BFloat16`. MPS uses
  float16, which converts fine, which is why the failure was invisible until
  someone ran on CPU. Fixed by upcasting with `.float()` in
  `harmfulness_probe.py` and `runner.py`; regression-tested in
  `backend/tests/test_probe.py`.

## Two rows are one measurement

`cosmic.json` and `arditi.json` are numerically identical to 17 significant
figures, including `probe_cosine`. COSMIC's scaffold uses the diff-of-means
direction as its per-layer candidate, so its search reduces to layer selection,
and it selected layer 8 — the layer the harness already hands Arditi. Same
vector, same result. Do not count them as independent evidence; the leaderboard
UI flags the duplicate for this reason.

## herring.json is from a separate invocation

Herring failed in the main sweep with
`TypeError: HerringCNA._make_neuron_zero_hook.<locals>.hook() got an unexpected
keyword argument 'hook'` — TransformerLens calls hooks by keyword and the
closure's parameter was named `hook_`. After the fix it was re-run alone with
the identical config, and every run-level and baseline field was verified equal
to the five-technique sweep (same seed → same split → same probe → same
baseline) before its row was merged into
`public/bench/refusal_bench_default.json`. The signature class of bug is now
covered by `backend/tests/test_hook_signatures.py`.

## Relationship to the other directories

- `docs/bench_partials/` — May 21 2026 HTTP-driven run. **Historical only**: not
  strict JSON, predates the determinism and CV-AUC fixes, and five of its six
  techniques errored. Do not cite.
- `docs/bench_result_local_6tech.json` — combined dump from the sweep, including
  the errored Herring row from before the fix.
- `public/bench/refusal_bench_default.json` — the merged, six-row artifact the
  frontend actually ships.
